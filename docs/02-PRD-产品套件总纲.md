## 1. 产品套件总纲

### 1.1 一句话定位

| 产品 | 名称 | 一句话定位 | 形态 |
|---|---|---|---|
| **A** | 游戏模式自动调度器（工作名：GameMode Pilot） | 检测到游戏启动，自动进入"战斗状态"；退出游戏，全部自动还原 | 常驻托盘守护程序（无感自动） |
| **B** | 中文游戏党优化全家桶（工作名：游优化 / GameOpt Box） | 一个顶十个的游戏工具箱，每项调整说人话、带风险等级、可一键还原 | 按需打开的工具箱（手动可控） |
| **C** | 帧时间诊断驱动的优化闭环（工作名：帧验 / FrameLab） | 先测量、再优化、前后对比报告，用数据证明每项调整有没有用 | 测量+诊断工作台（数据驱动） |

### 1.2 三产品关系与边界

```
                 ┌─────────────────────────────┐
                 │   PcOpt.Core（共享内核）      │
                 │  Tweak 引擎 / 还原 Journal    │
                 │  硬件检测 / 游戏检测 / 配置格式 │
                 └──────────┬──────────────────┘
                            │ 引用
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
   ┌─────────┐        ┌─────────┐         ┌─────────┐
   │ 产品 A   │        │ 产品 B   │         │ 产品 C   │
   │ 自动调度 │◄──────►│ 优化全家桶│◄───────►│ 帧时间诊断│
   └─────────┘        └─────────┘         └─────────┘
   A 调用 B 的 tweak    B 可一键召唤 A     C 调用 A 应用优化
   规则子集；A 不碰     设守护；C 用      再做前后对比
   深度手动配置         B 的规则做修复
```

**边界规则（防止范围蔓延）**：
1. **A 不做**：深度 tweak 库管理（120+ 项手动勾选属于 B）、基准测试与帧时间分析（属于 C）、硬件信息详情页（只展示会话必需的最小信息）。
2. **B 不做**：游戏进程自动监控与自动还原（属于 A——B 提供"开启守护"入口跳转 A）、帧时间捕获（属于 C）。
3. **C 不做**：常驻守护与游戏会话管理（调用 A 的引擎完成应用/还原）、通用 debloat tweak 库（复用 B 的规则）。
4. **三产品可独立安装、独立运行**；A/B/C 之间通过本地 IPC（命名管道）松耦合调用，任一缺失时优雅降级（隐藏对应入口并提示）。
5. 三产品**共用同一套视觉语言与文案规范**（见 2.6/3.6/4.6 引用的 UI 规范，详见第 5 章）。

### 1.3 共享内核 PcOpt.Core 需求（P0 级，三产品共同依赖）

| 模块 | 职责 | 关键要求 | 验收标准 |
|---|---|---|---|
| **TweakEngine** | 以"规则包"方式执行系统调整 | 动作类型至少覆盖：注册表读写/服务启动类型/计划任务/powercfg/进程优先级与亲和性/计时器分辨率(NtSetTimerResolution)/Shell 命令；条件执行（OS 版本+Build+CPU 架构+GPU 厂商）；**幂等**（重复执行结果一致）；每条规则可独立执行与还原 | 单条规则 apply/revert 单元测试覆盖率 ≥ 90%；规则包版本与 Win10 22H2/Win11 23H2/24H2/25H2 适配矩阵文档化 |
| **RestoreJournal（还原日志）** | 记录每次改动的原始值，支持安全还原 | 写入前捕获原值（注册表值/服务启动类型 GUID/电源方案 GUID 等）；JSON 原子写入（临时文件+重命名）；还原按 LIFO 顺序并做**还原后校验**；异常中断（崩溃/断电）后下次启动自动恢复 | 模拟进程强杀 100 次，重启后系统状态 100% 恢复到改动前；单条还原与全部还原均有自动化测试 |
| **HardwareDetect** | 硬件与传感器识别 | CPU（型号/架构/核线程/大小核）/GPU（厂商 NVIDIA/AMD/Intel、型号、显存）/内存（容量/频率）/磁盘（SMART 健康）/温度功耗（传感器）；**只读取、不改写** | 主流平台（Intel 12-15 代 / AMD 7000-9000 / NV 40-50 系 / AMD RX 7000-9000 / Intel Arc）识别正确率 ≥ 99%（测试机矩阵验证） |
| **GameDetect** | 游戏识别 | ① 平台库扫描：Steam / Epic / GOG / Xbox / **WeGame / 腾讯平台**（国产必做）；② ETW 进程创建事件实时监控；③ 内置热门游戏 executable 数据库（首发 ≥ 60 款，含 CS2/无畏契约/三角洲行动/PUBG/永劫无间/艾尔登法环/黑神话/瓦罗兰特等）；④ 反作弊组件识别（Vanguard/EAC/BattlEye/RICOCHET/TencentACE/VAC/FACEIT 的服务/驱动/注册表特征） | 60 款数据库游戏启动检测延迟 ≤ 3 秒；库扫描漏检率 ≤ 5%（测试库样本验证）；反作弊识别不产生任何误操作 |
| **ConfigFormat** | 配置与规则格式 | 规则包：**YAML + 数字签名（.sig）**，未签名/签名不符拒绝执行（借鉴 optimizerNXT 架构）；用户配置：JSON（版本化 schema，支持导出/导入）；profile：按"游戏 × 硬件档位"组合 | 篡改 YAML 后执行被拒绝并有明确错误提示；配置导出后在另一台同配置机器导入成功率 100% |
| **PcOpt.UI（共享 UI 组件库）** | 三产品共用的界面积木 | 风险等级标签、可逆开关卡片、二次确认对话框、进度与状态可视化、主题服务（深浅色/跟随系统）、托盘服务、Toast 通知 | 三产品 UI 走同一组件库，视觉走查（详见第 5 章）一次通过 |

### 1.4 演进路线建议（我的专业建议）

**建议顺序：共享内核 → 产品 A → 产品 B → 产品 C**。理由：

| 阶段 | 内容 | 理由 |
|---|---|---|
| 0（2~3 周） | PcOpt.Core + 共享 UI 组件库 | 三产品共同依赖；内核质量决定全套装死线；先定配置格式与 Journal 协议，避免后期返工 |
| 1（MVP） | **产品 A** | ① 价值主张最锐利（"装上就忘"），最易验证市场；② 只用到内核子集（游戏检测+会话引擎+还原），范围可控；③ 风险最高的是反作弊兼容，越早真实环境验证越好 |
| 2 | **产品 B** | 工作量最大但内核已就绪，主要是规则库内容生产（可社区化）；A 上线后收集的真实硬件分布可指导 B 的规则默认值 |
| 3 | **产品 C** | 技术风险最高（ETW 权限、帧时间口径、PresentMon 集成），需要 A/B 提供"可被测量的优化项"作为输入；作为 v2 差异化壁垒，此时团队也有桌面应用发布经验 |

**备选评估**：若用户希望最快见到"功能最全"的产品，可先 B 后 A——但不建议：B 是"手动工具箱"，无法验证"自动调度"这一核心差异化，且 tweak 库没有 A 的会话上下文（游戏进行中 vs 日常）会缺少关键维度。

## 2. 产品 A：游戏模式自动调度器（GameMode Pilot）

### 2.1 产品目标与定位

**目标**（源自调研报告 6.1）：
1. 游戏启动 → 自动应用该游戏/硬件组合的优化；游戏退出 → **全部自动还原**，日常使用零残留。
2. 全过程"无感"：装上就忘，不需要懂任何 tweak 知识。
3. 安全兜底行业标杆：反作弊自动降级、崩溃可恢复、每项可单独关闭。

**非目标**：不做手动 tweak 库（→B）、不做基准测试（→C）、不做硬件超频。

### 2.2 目标用户画像

| 画像 | 描述 | 核心诉求 |
|---|---|---|
| **竞技玩家小雷**（主） | 22 岁，CS2/无畏契约，中端配置（i5+4060），不会装系统不会 tweak，游戏卡顿只会重启 | "别让我学东西，游戏时自动变快，退出别把我电脑搞坏" |
| **网吧/电竞酒店网管**（次） | 管理 50~200 台机器，顾客客诉"玩着玩着卡了/重启后有问题" | 批量部署、出问题能一键还原、不碰顾客数据 |
| **直播/多开玩家**（次） | 游戏+OBS+语音同时跑，后台互相抢资源 | 游戏自动提优先级，退出后还回正常调度 |

### 2.3 用户故事（8 个）

1. 作为玩家，我想打开游戏时软件自动帮我优化系统，以便不用记任何设置。
2. 作为玩家，我想退出游戏后电脑自动恢复原样，以便日常使用不受影响。
3. 作为玩家，我想一眼看到"现在有没有在守护、游戏检测到没有、应用了哪些调整"，以便心里有数。
4. 作为玩家，我想自己决定某 adjust 项要不要开（比如我不想关通知），以便有控制感。
5. 作为网吧网管，我想在一台机器上配置好导出、批量部署到其他机器，以便不用逐台设置。
6. 作为网吧网管，我想任何调整都能一键全部还原，以便处理顾客客诉。
7. 作为玩家，我想软件自动识别我的反作弊环境并调整策略，以便不担心封号。
8. 作为玩家，我想软件崩溃或断电重启后系统是正常的，以便不担惊受怕。

### 2.4 需求池

#### P0（MVP 必须）

| ID | 功能 | 描述 | 验收标准 | 优先级理由 |
|---|---|---|---|---|
| A-P0-1 | 游戏库扫描 | 扫描 Steam/Epic/GOG/Xbox/WeGame/腾讯平台已装游戏，生成"我的游戏"列表 | 6 平台均能列出游戏名与可执行文件路径；用户可手动增删 | 自动调度的前提是知道"什么是游戏" |
| A-P0-2 | ETW 实时检测 | 监控进程创建事件，匹配数据库/用户列表，检测延迟 ≤ 3 秒 | 启动数据库内游戏，3 秒内触发会话；非游戏进程不误触发（测试 50 个常见软件） | 无实时检测则无"自动" |
| A-P0-3 | 优化会话引擎 | 游戏启动→按 profile 应用：暂停非必要服务（记录原启动类型）、进程优先级+亲和性、切 Ultimate Performance 电源计划、计时器分辨率 0.5ms、GPU 独显直连 profile、禁用全屏优化、清理一次待机内存、暂停通知 | 每项均可单独开关；应用顺序确定；全过程 ≤ 10 秒完成且有进度反馈 | 产品核心价值 |
| A-P0-4 | 退出自动还原 | 游戏退出→LIFO 还原全部改动+还原后校验；还原失败明确告知并保留 Journal | 模拟 30 款游戏进出，系统状态与改动前 100% 一致；Journal 可审计 | "退出还原"是安全承诺的生命线 |
| A-P0-5 | 状态日志与崩溃恢复 | 每次应用/还原写入原子 Journal；开机检测到未闭合会话自动恢复；提供"上次会话"查看 | 模拟强杀/断电 100 次，重启后 100% 恢复正常；主界面可查看最近 10 次会话 | 系统级工具的安全底线 |
| A-P0-6 | 反作弊检测与降级 | 检测 Vanguard/EAC/BattlEye/RICOCHET/ACE/VAC/FACEIT；命中内核级反作弊时，进程调度类操作自动切换为 IFEO 注册表方案 | 在装有 Vanguard 的机器上运行，会话正常应用且不触发任何反作弊拦截（真机测试报告） | 游戏党产品的生死线 |
| A-P0-7 | 首次运行向导 | 3 步：① 说明会改什么/自动创建还原点 ② 自动扫描游戏与硬件 ③ 推荐默认档位 | 向导完成率 ≥ 90%（可用性测试 5 人）；每步可跳过可回退 | 降低小白门槛 |
| A-P0-8 | 主界面（守护状态） | 常驻主窗口：守护开关、当前状态（守护中/游戏中/已还原）、最近会话、今日已省心提示 | 状态变化 ≤ 1 秒内反映到界面；见 2.7 线框 | 产品门面 |
| A-P0-9 | 托盘常驻 | 托盘图标+右键菜单（打开主界面/暂停守护 1 小时/退出）；游戏时图标变化 | 开机自启可选；托盘无闪退 | 守护程序的标准形态 |

#### P1（应当有）

## 4. 产品 C：帧时间诊断驱动的优化闭环（帧验 / FrameLab）

### 4.1 产品目标与定位

**目标**（源自调研报告 6.3）：
1. 内置基准测试与帧时间分析：先测量，再优化，**前后对比报告**证明/证伪每项调整。
2. 智能诊断：按症状（帧时间尖峰/DPC 延迟/内存膨胀/降频）匹配优化项，自动调用产品 A 的引擎应用，再复测对比。

## 5. UI 设计规范（三产品共用，重点章节）

> 用户不懂技术且明确要求：**界面好看、展示清晰、界面友好**。UI 质量是核心验收点。以下规范为验收依据。

### 5.1 设计原则

1. **好看**：WPF-UI（Fluent）设计语言；Win11 原生质感（Mica 背景、圆角卡片、微动效）；电竞感强调色但不喧宾夺主。
2. **清晰**：任何界面 3 秒内能回答"现在是什么状态、我能做什么、刚才发生了什么"；关键数字大而醒目。
3. **友好**：说人话；容错（随时可退）；不恐吓（危险项说清后果而非红线警告刷屏）；不撒谎（不承诺"提升 50% FPS"）。

### 5.2 设计 Token

| 类别 | 规范 |
|---|---|
| 框架 | WPF + WPF-UI (Fluent) + .NET 9；窗口使用 Mica/云母背景（Win11） |
| 主色 | 电竞蓝渐变 `#3B82F6 → #2563EB`；产品 C 可用青绿 `#10B981` 作辅助强调 |
| 状态色 | 运行/生效=绿 `#22C55E`；守护=蓝 `#3B82F6`；处理中=琥珀 `#F59E0B`；危险=红 `#EF4444`；中性=灰 |
| 字体 | 中文:微软雅黑 Microsoft YaHei UI；西文/数字:Segoe UI Variable；字号阶梯 12/14/16/20/28；数字用等宽变体 |
| 圆角 | 卡片 8px，按钮 6px，对话框 12px |
| 间距 | 4 基数：4/8/12/16/24；卡片内边距 16，卡片间距 12 |
| 阴影 | 卡片悬浮 0 2 8 rgba(0,0,0,.08)；不用重投影 |
| 主题 | 深/浅色 + 跟随系统；切换无闪烁；所有图表双主题配色 |

### 5.3 中文文案规范（说人话）

| 规则 | 正例 | 反例 |
|---|---|---|
| 用动词+结果，不用技术名词 | "让游戏少抢 CPU 的后台服务" | "禁用 SysMain/Superfetch 服务" |
| 术语首次出现必须 tooltip | "计时器分辨率（让游戏画面更跟手，详见?）" | "NtSetTimerResolution 0.5ms" |
| 风险三级且颜色区分 | 🟢安全/🟠注意/🔴危险+一句话后果 | 全部一个色或只有"警告" |
| 状态变化主动告知 | "已全部还原，共 6 项，你的电脑恢复正常了" | "Revert completed (6/6)" |
| 不夸大 | "可能改善帧时间稳定性，效果因电脑而异" | "立即提升 50% FPS!" |
| 按钮文案=动作结果 | [ 应用 ][ 还原 ][ 开始 60 秒测试 ] | [OK][Yes/No][Submit] |

### 5.4 状态可视化规范（核心）

- **全局状态条**：产品 A 主界面顶部大状态卡必须一眼可见三态：🛡️守护中（蓝）/🎮游戏中（绿，附游戏名与应用项数）/✅已还原（灰，附项数）。
- **生效计数徽标**：产品 B 每张已应用卡片绿色左边框+✓；导航"系统优化"显示"已生效 N 项"徽章；退出时若有 N 项生效必须弹窗询问保留或全部还原。
- **进度反馈**：任何超过 2 秒的操作必须有进度条或步骤文案（"正在切换电源计划… 2/6"）。
- **空状态**：无游戏/无历史时给插画+一句话+主行动按钮，不留白。
- **撤销通道**：Toast 通知带 [撤销] 按钮（适用项）。

### 5.5 危险操作二次确认规范

1. 触发条件：🔴危险级 tweak、卸载系统组件、关闭 Defender/更新、全部还原、导出覆盖。
2. 样式：红色描边对话框 + ⚠️ 图标 + **后果列表**（人话，≤3 条）+ "建议先创建还原点"勾选框（默认勾选）+ 主按钮[我了解，继续]（红色）。
3. 高危操作（关 Defender/更新）额外要求：输入"我了解风险"四字才能确认（防误触）。
4. 所有危险操作记入操作日志，可回查。

## 6. 合规红线（写入 PRD，所有产品强制执行）

> 源自调研报告第 7 章结论与用户确认（"改显卡型号"确认不做）。

| # | 红线 | 落地方式 |
|---|---|---|
| 1 | **不做显卡型号伪装**：不修改 HardwareInformation 字符串/驱动 INF 硬件 ID；硬件信息只真实展示 | 代码审查清单 + 自动化测试（断言注册表 GPU 类键未被写入） |
| 2 | **不注入游戏进程**：无 DLL 注入、无远程线程、无驱动级 hook | 架构约束：仅用户态 Win32 API；CI 静态扫描禁用 API 清单 |
| 3 | **不改游戏文件**：不碰游戏目录任何文件 | 文件系统访问审计日志 |
| 4 | **不 hook 内存**：不读写游戏进程内存 | 同 #2 |
| 5 | **反作弊检测自动降级**：检测到内核级反作弊（Vanguard/EAC/BattlEye/RICOCHET/ACE）时，进程调度类操作切换 IFEO 注册表方案；官网页明示兼容性声明与"自行验证 ToS"提醒 | 反作弊识别模块测试用例覆盖全部已知反作弊样本 |
| 6 | **默认不关闭安全功能**：Defender/自动更新/core isolation 类 tweak 默认折叠且默认关闭，开启需 5.5 危险确认流程 | 规则包默认值审计 |
| 7 | **所有 tweak 可还原**：每条规则必须有 revert 实现；应用前必须写 Journal；提供单条+全部还原 | TweakEngine 单元测试：apply→revert→状态一致 100% |
| 8 | （补充）**无遥测、无广告、纯本地**：除更新检查外无网络请求；隐私政策明示 | 网络访问审计（抓包测试） |
| 9 | **官方规则包只用可还原动作**（2026-10-14 用户确认）：Shell 命令 / powercfg 删除计划等不可自动还原的动作，不得出现在官方签名规则包中；用户自定义规则允许使用，但 UI 必须标注"此项退出后不会自动还原"且应用前需确认 | TweakEngine 加载官方签名包时校验并拒绝含此类动作的规则；自定义规则导入时打标 + 走 ConfirmDialog |
