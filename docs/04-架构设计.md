## 1. 技术选型（最终确认）

| 层     | 选型                                              | 许可证                       | 理由                                                             |
| ----- | ----------------------------------------------- | ------------------------- | -------------------------------------------------------------- |
| 运行时   | .NET 9                                          | MIT                       | PRD 已定；后续可对内核评估 NativeAOT 缩小体积                                 |
| UI 框架 | **WPF + WPF-UI（lepoco/wpf-ui）**                 | MIT                       | Fluent 设计语言、Mica 背景、深浅色开箱即用；便携绿色分发（不上 MSIX）                    |
| MVVM  | CommunityToolkit.Mvvm                           | MIT                       | 源码生成器减少样板代码                                                    |
| 依赖注入  | Microsoft.Extensions.DependencyInjection        | MIT                       | 内核与产品统一容器                                                      |
| 规则格式  | YamlDotNet                                      | MIT                       | YAML 规则包解析                                                     |
| 签名    | Ed25519（.NET 内置 `System.Security.Cryptography`） | —                         | 无外部依赖，跨平台可验证                                                   |
| 硬件传感器 | LibreHardwareMonitorLib                         | **MPL-2.0（文件级 Copyleft）** | 作 NuGet 依赖直接调用需 NOTICE 署名；不改其源码则无开源义务——⚠️ 集成前完成许可证核验并登记 NOTICE |
| 帧时间捕获 | PresentMon（Intel）                               | MIT                       | 子进程方式附带其二进制，NOTICE 署名                                          |
| 测试    | xUnit + FluentAssertions + Moq                  | Apache-2.0 / MIT / BSD    | 还原一致性是安全生命线，必须有自动化测试                                           |
| CI    | GitHub Actions                                  | —                         | build + 全量测试 + 许可证扫描 + YAML 签名校验                               |

**选型说明**：

- 不选 WinUI3：必须 MSIX 打包，损害"便携/绿色单文件夹"分发体验；WPF + WPF-UI 可达到同等 Fluent 观感（Dism++/SophiApp 同路线）。
- 不选 Electron/Tauri：内核重度依赖 Win32 原生 API（SCM/powercfg/ntdll/ETW），C# P/Invoke 最直接；Electron 体积与内存对常驻托盘程序不友好。

## 2. 总体架构

```
┌───────────────────────────────────────────────────────────┐
│  Products 层（3 个独立 WPF 应用，可分别安装运行）              │
│   GameModePilot(A)      GameOptBox(B)      FrameLab(C)     │
├───────────────────────────────────────────────────────────┤
│  PcOpt.UI（共享组件库，WPF 用户控件 + 主题服务）              │
│   StatusHeroCard / TweakCard / RiskBadge / ConfirmDialog   │
│   ProgressSteps / ToastHost / ThemeService / EmptyState    │
│   GameCard / MetricCompareTable / FrameChart / TrayService │
├───────────────────────────────────────────────────────────┤
│  PcOpt.Core（共享内核，零 UI 依赖，纯 .NET 类库）             │
│   TweakEngine    RestoreJournal    HardwareDetect          │
│   GameDetect     ConfigFormat      ServiceControl          │
│     (规则引擎)     (还原日志)        (硬件)                  │
│                   (配置/签名)        (系统 API 封装)          │
├───────────────────────────────────────────────────────────┤
│  系统 API 层：注册表 / SCM(服务) / powercfg / ntdll /        │
│  Win32(进程/计时器) / ETW / WMI / HidD(USB 轮询)            │
└───────────────────────────────────────────────────────────┘
```

**依赖规则（架构约束，违反即打回）**：

1. `Products → PcOpt.UI → PcOpt.Core → 系统 API`，单向依赖，禁止反向；
2. Products 之间**零项目引用**，只通过本地 IPC（命名管道）通信；
3. PcOpt.Core 不得引用任何 UI 框架或 WPF 程序集；
4. 所有触碰系统的代码只允许出现在 PcOpt.Core 的 handler 中（审计面集中）。

## 3. PcOpt.Core 模块设计

### 3.1 TweakEngine（规则引擎）

```csharp
public sealed class TweakRule
{
    public string Id { get; init; }                 // "svc.sysmain.disable"
    public string Category { get; init; }           // 性能|游戏|延迟|网络|隐私|体验
    public RiskLevel Risk { get; init; }            // Safe|Notice|Danger
    public string DisplayName { get; init; }        // 人话名："让游戏少抢 CPU 的后台服务"
    public string Description { get; init; }        // 人话说明
    public string[] ConsequenceHints { get; init; } // 后果提示（≤3 条）
    public OsCondition[] Conditions { get; init; }  // OS 版本+Build+CPU 架构+GPU 厂商
    public TweakAction[] Actions { get; init; }     // 有序动作列表
}

public enum RiskLevel { Safe, Notice, Danger }

public abstract record TweakAction;
public sealed record RegistrySetAction(string Path, string Name, object Value, RegistryValueKind Kind) : TweakAction;
public sealed record ServiceStartTypeAction(string ServiceName, ServiceStartMode Target) : TweakAction;
public sealed record ScheduledTaskAction(string TaskPath, bool Enable) : TweakAction;
public sealed record PowerCfgAction(PowerActionKind Kind, string Argument) : TweakAction;
public sealed record ProcessPriorityAction(string ProcessName, ProcessPriorityClass Priority, long? AffinityMask) : TweakAction;
public sealed record TimerResolutionAction(uint DesiredResolution100Ns) : TweakAction;
public sealed record ShellAction(string Command, string Arguments) : TweakAction;
```

- **执行流程**：`Load`（YAML + 签名验证，失败拒绝）→ `Match`（条件过滤不适配当前系统的规则）→ `Snapshot`（先写 Journal 再动手）→ `Apply`（幂等：重复执行结果一致）→ `Verify`（可选，读回确认）
- **还原流程**：`Revert(ruleId)` → 按 Journal LIFO 逐项恢复原值 → 校验一致
- **扩展点**：动作执行全部走 `ITweakActionHandler`，新增动作类型只需注册新 handler，引擎不改（开闭原则）
- **铁律**：先写 Journal 后执行；任何 handler 必须成对实现 Snapshot/Restore

### 3.2 RestoreJournal（还原日志）

```csharp
public sealed class Journal
{
    public string SessionId { get; init; }        // Guid
    public string Product { get; init; }          // GameModePilot | GameOptBox | FrameLab
    public DateTime StartedAt { get; init; }
    public JournalStatus Status { get; init; }    // Open | Closed | Recovered
    public List<JournalEntry> Entries { get; init; }
}

public sealed class JournalEntry
{
    public string RuleId { get; init; }
    public int ActionIndex { get; init; }
    public string OriginalValueJson { get; init; } // 原值快照（含"值不存在"语义）
    public DateTime AppliedAt { get; init; }
    public DateTime? RevertedAt { get; init; }
}
```

- 存储：`%ProgramData%\pcopt\journal\{sessionId}.json`
- 原子写：写 `.tmp` → `MoveFileEx(REPLACE_EXISTING)` 替换，防半页文件
- 开机恢复：启动时扫描 `Status==Open` 的 session → LIFO 恢复 → 标记 `Recovered` 并通知用户
- 验收：模拟强杀 100 次，重启后 100% 恢复原状（PRD A-P0-5）

### 3.3 HardwareDetect（硬件识别，只读）

- CPU：WMI `Win32_Processor` + `GetLogicalProcessorInformationEx`（大小核拓扑）
- GPU：注册表 `PCI\CCP_0000`… 类键只读解析（厂商/型号/显存），**只读，绝不写入**（合规红线 #1 有自动化测试断言）
- 内存/磁盘：WMI + SMART（`MSStorageDriver_FailurePredictStatus`）
- 温度/功耗：LibreHardwareMonitorLib 优先，失败降级 WMI `MSAcpi_ThermalZoneTemperature`（可用性有限，界面明示"部分传感器不可用"）
- 输出：`HardwareProfile`（不可变记录），供三产品消费

### 3.4 GameDetect（游戏与反作弊识别）

- **库扫描**：Steam（`libraryfolders.vdf` + `appmanifest.acf`）、Epic（`.manifest`）、GOG、Xbox（`Get-AppxPackage`/WMI）、WeGame/腾讯（目录探测 + 注册表，**需真机实测后回填**）
- **ETW 实时监控**：`Microsoft-Windows-Kernel-Process` provider，进程创建事件 → 匹配 executable 名/SHA256 → 延迟 ≤ 3 秒
- **游戏数据库**：`rules/games.yaml`（首发 ≥ 60 款：executable、平台、反作弊标记、推荐档位），社区可 PR 增补
- **反作弊识别**：服务名/驱动文件/注册表特征匹配 → `AntiCheatProfile { None, Kernel, UserMode }`；命中 Kernel 时 SessionEngine 自动降级为 IFEO 方案（A-P0-6）

### 3.5 ConfigFormat（配置与签名）

- **规则包**：`rules/tweaks/*.yaml` + `rules/public.key`；Ed25519 签名 `.sig`；加载时验签，未签名/不符拒绝执行并提示
- **用户配置**：`%AppData%\pcopt\{product}\config.json`，`schemaVersion` 版本化；导入前 schema 校验 + 逐项预览
- **Profile**：`{ gameId × hardwareTier → 强度档 + 开关组合 }`，随用户配置存储

### 3.6 ServiceControl（系统 API 封装，内核基础设施）

| 能力       | API                                                       | 备注                           |
| -------- | --------------------------------------------------------- | ---------------------------- |
| 服务启动类型   | SCM `ChangeServiceConfigW`                                | 改前记录原启动类型进 Journal           |
| 服务暂停/恢复  | `ControlService(SERVICE_CONTROL_PAUSE/CONTINUE)`          | 需服务 `AcceptPause`            |
| 电源计划     | `powercfg /list /import /setactive /delete`               | Ultimate Performance GUID 内置 |
| 进程优先级/亲和 | `SetPriorityClass` / `SetProcessAffinityMask` / EcoQoS    | Win11 可用 CPU Sets 精细调度       |
| 计时器分辨率   | `NtSetTimerResolution`（ntdll P/Invoke）                    | 进程退出时恢复原值                    |
| IFEO 降级  | `HKLM\...\Image File Execution Options\{exe}\PerfOptions` | 仅内核反作弊命中时使用                  |
| USB 轮询率  | `HidD_GetFeature/SetFeature`                              | B-P0-4，兼容主流键鼠                |

## 4. 三产品架构

### 4.1 产品 A：GameModePilot（自动调度器）

```
GameModePilot/
├── App.xaml                     # 启动 + DI 容器 + 单实例
├── Services/
│   ├── SessionEngine.cs         # 会话编排：Begin/Apply/Revert/Verify（核心）
│   ├── GameWatcher.cs           # ETW 订阅 + 进程匹配
│   ├── IpcServer.cs             # 命名管道服务端（供 B/C 调用）
│   ├── TrayService.cs           # 托盘图标与菜单
│   └── UpdateChecker.cs         # GitHub Releases 检查（默认关）
├── ViewModels/                  # MainViewModel / WizardViewModel / ...
└── Views/                       # 主界面 / 向导 / 游戏列表 / 会话历史 / 设置
```

**游戏会话时序**：

```
ETW 进程创建事件
  → GameWatcher.OnGameStarted(game)
  → AntiCheatDetect()
      ├─ UserMode/None → 标准方案
      └─ Kernel        → IFEO 降级方案
  → SessionEngine.BeginSession(game, profile)
      → RestoreJournal.Begin() → TweakEngine.Apply(逐项, IProgress)
  → 游戏中：托盘图标变化 + 主界面三态卡（🎮 游戏中）
  → ETW 进程退出
  → SessionEngine.EndSession()
      → TweakEngine.Revert(LIFO) → Verify → Toast "已全部还原，共 N 项"
```

**IPC 契约**（命名管道 `\\.\pipe\pcopt.gamemodepilot`，JSON-line 协议）：

- `{"cmd":"status"}` → 守护状态/当前会话
- `{"cmd":"enable","minutes":60}` / `{"cmd":"disable"}` → 暂停/恢复守护（B 调用）
- `{"cmd":"applyProfile","ruleIds":[...]}` / `{"cmd":"revertAll"}` → C 调用
- 任一产品缺失时调用方优雅降级（隐藏入口 + 提示安装）

### 4.2 产品 B：GameOptBox（优化全家桶）

```
GameOptBox/
├── Services/
│   ├── RuleBrowser.cs           # 规则加载/搜索/分组/状态追踪
│   ├── LauncherService.cs       # 拉起 A（管道探测）/ C（进程启动）
│   └── HealthScoreService.cs    # 首页健康分算法（文档化权重）
├── ViewModels/  └── Views/      # 首页/系统/游戏/内存/监控/显示/网络/清理/驱动/设置
└── rules/tweaks/*.yaml          # 规则库随包发布，启动验签加载
```

- 与 A 联动：管道探测 A 是否运行 → "开启自动守护"入口；未安装则引导下载
- 与 C 联动："去测一测"启动 FrameLab 可执行文件
- tweak 卡片三态（未应用/已应用/危险）严格按 PRD 5.4/5.5 规范

### 4.3 产品 C：FrameLab（帧时间诊断）

```
FrameLab/
├── Services/
│   ├── PresentMonHost.cs        # 子进程管理：启动/参数/CSV 落盘/清理
│   ├── FrameAnalyzer.cs         # 解析 + 指标：平均FPS/1%Low 双算法/卡停检测
│   ├── Diagnoser.cs             # 症状匹配：帧尖峰+DPC/standby/降频/GPU 瓶颈
│   └── ReportExporter.cs        # PNG/CSV 导出
├── ViewModels/  └── Views/      # 测试台/报告/诊断/历史/设置
└── ThirdParty/PresentMon/       # 附带 PresentMon 二进制（MIT，NOTICE 署名）
```

- **PresentMon 集成方式（已定夺）**：子进程方式——`PresentMon --process_name {exe} --output_csv {file} --timed 60`；避免 C++/CLI 链接与分发复杂度；与 CapFrameX 实践一致
- **A 未安装时的最小引擎**：电源 + 计时器 + 内存清理三项（内核已有能力，PRD 4.7-2）
- 口径透明：报告必须标注 1% Low 算法（time-based / percentile 双算）与 HAGS 影响说明（PRD 4.7-3）

## 5. 关键设计决策（ADR 摘要）

| #     | 决策                     | 理由                                    |
| ----- | ---------------------- | ------------------------------------- |
| ADR-1 | Monorepo + 共享内核        | 内核接口变更需同步三产品；一次 CI 全量验证               |
| ADR-2 | WPF + WPF-UI，不用 WinUI3 | 免 MSIX 打包，保持便携分发；Fluent 观感等价          |
| ADR-3 | YAML + Ed25519 签名规则包   | 可审计 + 防篡改 + 社区可贡献（借鉴 optimizerNXT）    |
| ADR-4 | PresentMon 子进程集成       | 免 C++ 链接；分发即附带二进制                     |
| ADR-5 | 命名管道 IPC（JSON-line）    | .NET 原生、本地、零额外依赖；产品可独立安装              |
| ADR-6 | 传感器 LHM 依赖 + WMI 兜底    | 自研 EC 读取成本高；MPL-2.0 作依赖使用合规（需 NOTICE） |
| ADR-7 | Journal 先写后做 + LIFO 还原 | 崩溃安全是系统级工具的生命线（PRD 红线 #7）             |

## 8. 跨文件约定（共享知识，所有代码生效）

1. **命名**：规则 Id `分类.对象.动作`（`svc.sysmain.disable`）；配置键 camelCase；私有字段 `_camelCase`；异步方法 `Async` 后缀。
2. **错误处理**：内核公开 API 返回 `Result<T>`，不跨模块抛异常；UI 层统一 Toast 展示。
3. **日志**：`Microsoft.Extensions.Logging` + 文件 provider；**用户数据、硬件序列号、路径中的用户名绝不进日志**。
4. **还原优先**：任何 Apply 之前 Journal 必须已落盘；失败时保证系统可恢复是最高优先级。
5. **UI 线程**：ViewModel 命令全部 async；超过 2 秒的操作必须报 `IProgress<T>`（PRD 5.4）。
6. **文案**：所有面向用户的字符串走资源文件（`Strings.zh-CN.xaml`），遵守 PRD 5.3 说人话规范。
7. **许可证头**：每个 `.cs` 文件首行 MIT 短版权头（开源计划第 3 章）。
8. **只读硬件**：GPU 类注册表键只读，CI 有断言测试（合规红线 #1）。
