# 开源计划：pcopt-suite（游戏党 PC 优化套件）

> **版本**：v1.0 ｜ **日期**：2026-10-14
> **依据**：《01-市场调研-游戏党PC优化.md》已验证数据 + 《02-PRD-产品套件总纲.md》+ 用户确认（项目可参考 GitHub 开源项目；后续将开源发布至 GitHub）

## 1. 开源目标与策略

### 1.1 为什么开源

| 目标 | 说明 |
|---|---|
| **信任基础** | 系统级优化工具"要改用户的电脑"，开源可审计是最强的信任声明（对比 GamePP 等闭源商业工具） |
| **合规自证** | 合规红线（不注入 / 不改游戏文件 / 不做显卡伪装 / 无遥测）通过公开源码可验证，直接回应反作弊社区质疑 |
| **社区共建** | tweak 规则库、游戏 executable 数据库、硬件兼容报告最适合社区贡献（借鉴 optimizerNXT 的 YAML 包 Hub 模式） |
| **分发与反馈** | GitHub Releases + Issues 是零成本分发与反馈通道，与 PRD A-P1-6（更新检查）天然衔接 |

### 1.2 开源时间线

| 阶段 | 动作 |
|---|---|
| 开发期（现在起） | 按开源规范写代码：源文件带许可证头；第三方代码必须可追溯；不提交任何密钥 / 个人信息 / 编译产物 |
| MVP 可用时 | 公开仓库（共享内核 + 产品 A 达到 PRD 验收标准后），先 Public 再宣传 |
| 持续 | 语义化版本 Release；规则库与游戏数据库社区化运营 |

### 1.3 仓库形态：Monorepo（单仓库多项目）

三产品与共享内核版本强耦合（内核接口变更必须同步三产品），Monorepo 最合适：一次 CI 全量验证、内核单一版本、Issue 集中管理。**不采用 multi-repo**（内核版本同步成本高，社区贡献门槛高）。

## 2. 许可证选型（⬜ 待用户拍板）

### 2.1 候选对比

| 许可证 | 权限 | 主要约束 | 允许闭源商用 | 社区采用度 | 适配度 |
|---|---|---|---|---|---|
| **MIT** | 任意使用 / 修改 / 分发 / 闭源再分发 | 仅保留版权声明与许可证文本 | ✅ | ⭐ 最高 | ⭐⭐⭐ **✅ 已采用** |
| **Apache-2.0** | 同 MIT，另含明确专利授权条款 | 保留声明 + 修改文件需标注 + NOTICE 文件 | ✅ | ⭐⭐ | ⭐⭐ 备选 |
| **GPL-3.0** | Copyleft：衍生作品必须同协议开源 | 网络使用也视为分发；闭源集成受限 | ⚠️ 受限 | ⭐ 中 | ⭐ 不推荐首发 |

### 2.2 ✅ 已采用：MIT（2026-10-14 用户拍板："公开，大家都可以使用"）

1. **与参考项目文化一致**：GameShift / winutil / Win11Debloat / Sophia-Script / PresentMon / CapFrameX 均为 MIT，是这类工具的事实标准；
2. **传播最大化**：游戏党社区的教程、二开、装机渠道预装都优先选 MIT，无 Copyleft 摩擦；
3. **现阶段主要矛盾是声量与信任**，不是防白嫖；若未来担心竞品直接闭源 Fork，可学 Winhance 增加 PolyForm Shield 补充条款或改双许可，届时再议。

### 2.3 参考项目许可证与借鉴边界（源自调研报告已验证数据）

| 项目 | 许可证 | 可否复制代码 | 借鉴方式 |
|---|---|---|---|
| GameShift | MIT | ✅ 可（保留版权声明） | **架构重点参考**：state journal / 反作弊自动降级 |
| winutil / Win11Debloat | MIT | ✅ | preset 分层、tweak 组织方式 |
| Sophia-Script / SophiApp | MIT | ✅ | tweak/还原配对、VAC 友好声明 |
| PresentMon | MIT | ✅（须署名） | 产品 C 核心依赖，子进程或库集成 |
| CapFrameX | MIT | ✅ | 帧时间报告观感参考 |
| BCU | Apache-2.0 | ✅（保留 NOTICE） | Steam 游戏识别、卸载残留扫描思路 |
| privacy.sexy | MIT | ✅ | 脚本组织方式 |
| Dism++ | MIT（仓库仅多语言资源，主程序源码未完整开源） | ❌ | 功能标杆参考 |
| Atlas / optimizerDuck / optimizerNXT / memreduct / simplewall / NexBox | GPLv3 / GPL-3.0 | ❌ **禁止复制入本仓库** | 仅思路参考 |
| Winhance | PolyForm Shield（source-available，非 OSI） | ❌ | 仅思路参考 |

**铁律**：
1. 复制代码仅限 MIT / Apache-2.0 / BSD 系，且保留原版权声明；
2. GPL 系项目只看思路、不复制任何代码（避免许可证传染）；
3. 集成任何第三方库前必须在 `NOTICE` 登记，并经 CI 许可证扫描；
4. 第 2.3 节中"待核验"项在相关代码集成前完成核验并回填本表。

> **现状（T38/T39 更新）**：上表"待核验"项（privatezilla / RyTuneX / fps-booster / MPO-GPU-FIX）
> 与全部 GPL / source-available 项**均未复制任何代码，仅作思路参考**，因此当前不构成任何许可证义务。
> 该行不作为首发阻塞项；若未来要引入其代码，须先完成核验并回填。

## 5. 签名与更新机制（开源场景）

PRD 要求 YAML 规则包签名防篡改（借鉴 optimizerNXT）。开源场景下的密钥管理方案：

| 问题 | 方案 |
|---|---|
| 签名私钥存放 | **绝不出现在仓库和 CI 日志**。维护者离线保管；CI 签名使用 GitHub Actions Secrets |
| 公钥分发 | 公钥随仓库发布（`rules/public.key`），任何人可验证官方规则包 |
| 官方规则包 | 随 Release 发布已签名包；仓库内 `rules/` 为源码，社区可审计，由维护者签名后发布 |
| 社区规则包 | 社区作者可自签名（附带公钥）或提交 PR 合入官方包；用户导入第三方包时提示"非官方签名，风险自担" |
| 用户自建规则 | 允许导入未签名自定义 YAML，导入时弹窗告知风险（本地工具，用户有权调整自己的电脑） |
| 更新通道 | GitHub Releases（产品 A 的更新检查读取 Releases API，默认关闭、可一键关，符合"默认完全离线"确认项） |

## 6. 安全与合规（开源强化项）

延续 PRD 第 6 章合规红线 8 条，开源场景追加：

1. **SECURITY.md**：漏洞私下报告流程（GitHub Security Advisory / 专用邮箱），承诺响应时限；
2. **README 显著位置**：反作弊兼容性声明（不注入 / 不改游戏文件 / 不 hook 内存 / 内核反作弊自动降级）+ "请自行验证游戏 ToS" 提醒；
3. **无遥测可验证**：源码公开即承诺；CI 增加网络调用白名单检查（除更新检查外零外联）；
4. **免责声明**：系统级工具标准免责（使用前创建还原点、风险自担、不保证 FPS 提升）；
5. **敏感功能默认关闭**：Defender / 更新类默认折叠 + 默认关闭（PRD 红线 #6），源码默认值需评审；
6. **发布前审查**：无硬编码密钥 / 个人信息 / 内网地址；git 历史干净（必要时 squash 后首发）。
